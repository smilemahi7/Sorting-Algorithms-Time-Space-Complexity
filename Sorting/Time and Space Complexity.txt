



Asymptotic Notation:
		
	Asymptotic Notation in Data Structure is a way to describe how the time or space needed by an algorithm grows as the size of the input grows. It helps us understand how efficient an algorithm is when we have very large inputs.
		Example - We have different ways to solve a problem, like sorting a list of numbers. Some ways are fast when the list is short, but they might become very slow when the list is long. Asymptotic notation helps us compare these methods by focusing on how they perform when the input size gets really big.
	
	3 Types of Asymptotic Notation in Data Structure:
	
		Omega Notation (Ω): 
			This represents the best case performance for an algorithm, setting a lower bound on how fast the code can perform. It’s noted as Ω(n).
			Omega Notation is used to describe the lower bound of an algorithm's running time. It tells us the minimum time an algorithm will take to complete, given the size of the input.
			It represents the best-case time complexity of an algorithm. This notation calculates the minimum time an algorithm takes to execute completely.
			It is define as lower bound and lower bound on an algorithm is the least amount of time required ( the most efficient way possible, in other words best case).		

			How it Measures the Lower Bound?
				Omega notation focuses on the best-case scenario. It helps us understand the least amount of time or space an algorithm will require.
				
			Common Examples:
				Ω(1): Constant time. The algorithm takes at least a constant amount of time, regardless of the input size.
				Ω(n): Linear time. The algorithm takes at least linear time as the input size grows.

		Theta Notation (Θ): 
			This represents the average, typical case performance for an algorithm. It’s noted as Θ(n×p).
			Theta Notation is used to describe the exact bound of an algorithm's running time. It tells us the average-case scenario, where the running time is bound both above and below by the same function.
			It represents the average-case time complexity of an algorithm. This notation calculates the average time an algorithm takes to execute completely.
			It is define as tightest bound and tightest bound is the best of all the worst case times that the algorithm can take.

			How it Measures the Exact Bound?				
				Theta notation focuses on the typical running time of an algorithm. It shows that the algorithm's running time is both at least and at most a certain function of the input size.
			
			Common Examples:
				Θ(1): Constant time. The algorithm takes a constant amount of time, regardless of the input size.
				Θ(n): Linear time. The algorithm's running time grows linearly with the input size.
		
		Big Oh Notation (O): 
			This represents the worst-case performance for an algorithm, setting an upper bound on how slow your code can be. It’s noted as O(n²).
			Big O Notation is used to describe the upper bound of an algorithm's running time. It tells us the maximum time an algorithm could take to complete, given the size of the input.
			It represents the worst-case time complexity of an algorithm. This notation calculates the maximum time an algorithm takes to execute completely.
			It is defined as upper bound and upper bound on an algorithm is the most amount of time required ( the worst case performance).

			How it Measures the Upper Bound?
				Big O notation focuses on the worst-case scenario. It helps us understand the maximum time or space an algorithm will require, regardless of the input's specifics.
			
			Common Examples:
				O(1): Constant time. The algorithm takes the same amount of time regardless of the input size. Example: Accessing an element in an array.
				O(n): Linear time. The algorithm's running time grows linearly with the input size. Example: Iterating through a list.
				O(n^2): Quadratic time. The running time grows quadratically as the input size increases. Example: Bubble sort.
	
	
	The efficiency and performance of algorithm depends on 2 parameters:

		1. Time Complexity:
		
			The amount of time an algorithm takes to run as a function of length of input.
			
			Time complexity with a real-life example:
				
				Let’s take the example of the process of searching for a name in a contact list on your phone. If the contacts are unsorted, you might have to look through each name one by one until you find the right one. It becomes increasingly inefficient as the number of contacts increases. This scenario can be compared to a linear search algorithm, which has a time complexity of O(n), where n represents the number of contacts. However, if the contacts are sorted alphabetically, you can use a more efficient search method, like binary search, which cuts down the list of potential matches in half with each step, leading to a time complexity of O(log n).	Here, the time it takes to find a contact becomes much slower than the size of the contact list, showing how crucial efficient algorithms are for performance, especially with large datasets.
			
			"Time complexity" is typically expressed using "Big-O" notation because it describes the upper bound of an algorithm's runtime, which is the most commonly used metric for comparing algorithm efficiency, whereas Omega notation represents the lower bound and Theta notation represents the exact bound. 
			
			Key points about "Big-O" notation:
				Big-O notation usually focuses on the worst-case scenario, meaning it tells you how long an algorithm could potentially take to run for a given input size.
				Developers are often most concerned with the potential worst-case performance of an algorithm, Big-O notation provides a valuable tool for comparing and analyzing different algorithms.
				
			Types of Time Complexity:
				1. Constant Time: - O(1)
					The execution time is constant and does not change with the size of the input.
					Example - Accessing an array element.
				2. Logarithmic Time: - O(log n)
					The execution time grows logarithmically as the input size increases.
					Example - Binary search.
				3. Linear Time: - O(n)
					The execution time grows linearly with the input size. 
					Example - Finding max in an array.
				4. Linearithmic Time: - O(n log n)
					Common in efficient sorting algorithms like mergesort and heapsort. 
					Example - Merge sort.
				5. Quadratic Time: - O(n^2)
					The execution time grows quadratically with the input size, common in algorithms with nested loops. 
					Example - Bubble sort.
				6. Exponential Time: - O(2^n)
					The execution time doubles with each additional element in the input, typical of certain recursive algorithms.
					Example - Recursive Fibonacci.
				7. Factorial Time: - O(n!)
					It complexity grows extremely fast with the increase in input size and is generally unsustainable even for relatively small n.
					Example - Generating permutations.
			
		2. Space Complexity:
		
			The amount of memory an algorithm takes to execute completely.
			
			Space complexity with a real-life example:
			
				The amount of space you need to store all your school supplies in your backpack. Imagine you have different subjects and each subject has its own set of books, notebooks, and stationery. The space complexity of your backpack is the total space needed to fit all these items. If you have a simple subject like Math, you might only need one book and a notebook, taking up a small amount of space. But for a project-heavy subject like Art, you might need multiple sketchbooks, paints, brushes, and more, taking up much more space. Similarly, in algorithms, some tasks require only a little memory, while others need a lot more. Understanding space complexity helps us choose the best way to pack our backpack (or write our algorithm) so that we use the least amount of space possible. This ensures we can fit everything we need without running out of room.
			
			Space complexity is composed of two main components: fixed part and variable part.

				1. Fixed Part: - O(1)
					This includes the space required for constants, simple variables, fixed-size data structures, and the code itself. It is the memory that does not change regardless of the input size.
					Examples:
						Space needed for storing constants like numbers or fixed-size arrays.
						Memory used by the program code and instructions.

				2. Variable Part: - O(n)
					This includes the space required for dynamic memory allocation, recursive stack space, and temporary variables whose size depends on the input size.
					Examples:
						Space needed for dynamic data structures like linked lists, trees, or graphs, which grow with the input size.
						Memory used for the recursion stack during recursive function calls.
						Temporary variables and data structures used during the execution of the algorithm.
						
			Types of Space Complexity:
				1. Constant Space: - O(1)
					The execution space is constant and does not change with the size of the input.
					Example - Finding max in an array.
				2. Logarithmic Space: - O(log n)
					The execution space grows logarithmically as the input size increases.
					Example - Binary search recursion depth.
				3. Linear Space: - O(n)
					The execution space grows linearly with the input size. 
					Example - Storing a list of n elements.
				4. Linearithmic Space: - O(n log n)
					Common in efficient sorting algorithms like mergesort and heapsort. 
					Example - Merge sort.
				5. Quadratic Space: - O(n^2)
					The execution space grows quadratically with the input size, common in algorithms with nested loops. 
					Example - 2D matrix operations.
				6. Exponential Space: - O(2^n)
					The execution space doubles with each additional element in the input, typical of certain recursive algorithms.
					Example - Subset sum problem using recursion.
				7. Factorial Space: - O(n!)
					It complexity grows extremely fast with the increase in input size and is generally unsustainable even for relatively small n.
					Example - Generating all permutations of a string.
	
	
	How to Calculate Asymptotic Notation of Algorithm?
	
		1. Identify the Basic Operations:
			Determine the most significant operation(s) that contribute to the running time (e.g., comparisons, assignments).

		2. Count the Number of Operations:
			Analyze the code to count how many times the basic operations are executed relative to the input size n.

		3. Express the Running Time as a Function:
			Write a function that represents the number of operations as a function of n.

		4. Simplify the Function:
			Focus on the dominant terms and ignore lower-order terms and constant factors.

		5. Determine the Asymptotic Notation:
			Based on the simplified function, determine the appropriate asymptotic notation (Big O, Omega, or Theta).


	Common Asymptotic Notations and Their Importance?
	
		O(1) - Constant Time:
			An algorithm with constant time complexity has a running time that does not change with the size of the input. It takes the same amount of time to execute regardless of the input size.
			This is the most efficient time complexity. Operations like accessing an element in an array by index or performing a basic arithmetic operation are O(1).

		O(log n) - Logarithmic Time:
			An algorithm with logarithmic time complexity has a running time that grows logarithmically with the input size. It is efficient for large inputs.
			Algorithms that divide the problem size in each step, like binary search, have logarithmic time complexity.

		O(n) - Linear Time:
			An algorithm with linear time complexity has a running time that grows linearly with the input size.
			Algorithms that iterate through all elements of the input, like finding the maximum value in an array, have linear time complexity.

		O(n log n) - Linearithmic Time:
			An algorithm with linearithmic time complexity has a running time that grows in proportion to n log n. It is more efficient than quadratic time but less efficient than linear time for large inputs.
			Efficient sorting algorithms like merge sort and quicksort have linearithmic time complexity.

		O(n^2) - Quadratic Time:
			An algorithm with quadratic time complexity has a running time that grows quadratically with the input size.
			Algorithms with nested loops that process each pair of input elements, like bubble sort, have quadratic time complexity.

		O(2^n) - Exponential Time:
			An algorithm with exponential time complexity has a running time that grows exponentially with the input size.
			Algorithms that solve problems by recursively exploring all possibilities, like the recursive solution for the Fibonacci sequence, have exponential time complexity.

		O(n!) - Factorial Time:
			An algorithm with factorial time complexity has a running time that grows factorially with the input size.
			Algorithms that generate all permutations of an input, like solving the traveling salesman problem by brute force, have factorial time complexity.

	
	Best, Worst, and Average Case Analysis?
	
		When analyzing algorithms, it's important to consider their performance under different scenarios. These scenarios are referred to as the best case, worst case, and average case.
		Each case provides insight into how the algorithm behaves under different input conditions.

		Best Case Analysis:
			The best case scenario refers to the input for which the algorithm performs the minimum possible number of operations.
			This represents the most favorable scenario for the algorithm.

			Example:
			Bubble Sort: The best case occurs when the input array is already sorted. The algorithm performs O(n) comparisons and no swaps.

		Average Case Analysis:
			The average case scenario refers to the expected performance of the algorithm over all possible inputs of a given size.
			It provides an overall picture of the algorithm's efficiency.

			Example:
			Linear Search: The average case occurs when the target element is located somewhere in the middle of the array. The algorithm performs O(n/2) comparisons on average, which simplifies to O(n).
		
		Worst Case Analysis:
			The worst case scenario refers to the input for which the algorithm performs the maximum possible number of operations.
			This represents the least favorable scenario for the algorithm.

			Example:
			Quick Sort: The worst case occurs when the pivot selection results in the most unbalanced partitions, such as when the smallest or largest element is always chosen as the pivot. The algorithm performs O(n^2) comparisons.
